# 图文混合文档 RAG 实现与启用

2026-10-02：首版代码已加入；数据库迁移、真实模型端到端验收和生产部署尚未执行。

## 启用步骤

1. 先执行 `docs/schemas/migrations/20261002-rag-file-sources.sql`，再执行 `docs/schemas/migrations/20261002-rag-visual-assets.sql`。

   如果后续重跑文件数据源迁移，必须再重跑视觉迁移以恢复原子发布保护。
2. 在连接设置里配置并选择支持图片的视觉模型。入库不会回退到未明确选择的默认付费模型。
3. 渲染运行环境需要 Poppler 的 `pdftoppm`；Docker runner 已加入 poppler-utils。本机可通过 `RAG_PDF_RENDER_BIN` 指定可执行文件的绝对路径。
4. 上传文件后，在知识库文件列表点击“启用视觉索引”。确认提示说明图片发送给配置的模型及相应费用。也可对文件 POST `{ "enableVisual": true }` 到 `/api/knowledge/files/<id>`。
5. 使用现有 ingestion worker 处理任务：`npm run rag:ingestion:work`。视觉解析仍复用文件入库队列，不是独立视觉队列。
6. 定期运行 `npx tsx scripts/knowledge-visual-cleanup.ts`，清理超过一天的未发布/旧 generation 及删除资源的 Storage 对象。脚本未自动配置调度。

## 已实现

- PDF 按物理页面创建视觉资源，包括空文字/扫描页；描述阶段整页渲染，未渲染页面可以在读取工具中按需渲染。
- DOCX 受限提取 PNG/JPEG 原图，保留 alt 和最终规范化正文 offset；文字索引不包含图片字节或内部标记。
- 视觉模型同时生成可见文字转写和图形描述；视觉代理作为额外 documents chunks，与正文一起原子发布。
- generation 比较并交换、文件 SHA 校验、入库 worker lease 校验、租约续期、删除资源的持久清理任务。
- search_notes 返回模型可见资源 ID，相关视觉候选可保留为弱证据，以免核实前被文字充分性检查丢弃。
- read_knowledge_visual 只接受本轮检索授权、当前用户、当前版本的资源；单次最多 3 张、最多 2 次调用。
- 主模型支持视觉时，在工具收据后追加实际图片输入；非视觉模型通过明确配置的视觉模型获得文字观察结果。
- 模型请求前才把引用转成图片字节，历史消息/SSE/工具 artifact 不保存新增图片 base64；调用层关闭输入输出 telemetry。
- 视觉出处链接通过同源鉴权读取，不直接暴露 Storage 签名 URL；支持 PDF 物理页码标题和图片查看。
- visual_loaded 与 visual_observation 区分；仅加载成功的证据不会通过词面支持检查。观察记录仍是可出错的模型结果，校验不宣称事实真值证明。

## 首版限制与设计差异

- 不是完整执行设计稿的所有阶段：无独立 OCR 引擎、结构化 JSON 观察 schema、独立视觉增强队列、区域检测、高清裁剪、多模态 embedding 或 Notion 图片导入。
- 图片文字转写由视觉模型完成，质量取决于所选模型，不能保证表格精确读数。
- 每次入库最多分析 20 张，另有约 240 秒分析启动窗口；所有页面仍登记资源，但未分析内容无法按图中实体召回。重新入库目前重新分析前段资源，不支持选择后续页补索引。
- Markdown/HTML 保留原来的图片占位符，不导入 data URI/远程/相对路径图片。DOCX 只支持 PNG/JPEG，其他格式标记不可用；没有 Word 排版页码或 SmartArt 完整渲染。
- 当前应用 provider 是 OpenAI-compatible；内部 Anthropic 格式的工具结果可以携带图片引用，但没有新增直接 Anthropic provider。每个实际服务仍需要验证图片、工具调用及续写组合兼容性。
- 视觉增强在单次文件任务中完成后发布，失败可部分发布正文与资源清单；尚无“先发布文本、单独后台增强”的两队列工作流。
- 每次视觉重建重新生成 generation 和描述，不提供持久描述缓存；费用按每次调用产生。观察工具返回 token 与费用估算，入库费用暂未接统计面板。
- Poppler 子进程有超时、输出尺寸与字节限制，但尚未加入 OS 级独立内存/CPU 沙盒。面向不可信大量文件的生产环境应运行受限 worker 容器。
- 用户配置的模型、容器构建、数据库事务/迁移、前端交互和端到端视觉正确率还需要真实环境验收。

## 建议验收

先用小型 PDF 验证：一页普通正文、一页纯矢量流程图、一页扫描图片。开启视觉索引后，问只出现在图片中的实体与箭头方向；检查 search_notes 命中 visual_proxy、调用原图读取、答案页码引用可打开。另用 DOCX 验证带 alt 的图片及无 alt 图片。

测试中覆盖了权限、版本撤销、扫描页、DOCX 图片位置、预算、模型传图请求结构及现有功能回归；模拟测试不替代真实视觉模型答案质量或数据库竞态测试。
